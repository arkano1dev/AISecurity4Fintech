# VaultRAG: secure retrieval over internal documents

## User story

As a compliance analyst, I want to ask questions over internal policies and
procedures and receive answers with citations, so that I can verify every claim
against the source — without personal data ever reaching the model.

## Why this story

VaultRAG is the first application that exercises the full platform flow: it
ingests documents, redacts PII through the shared `pii-proxy`, embeds with a
local model, retrieves the most relevant chunks, generates a grounded answer
through Ollama, and writes every query to the append-only `audit-log`.

## Acceptance criteria

### V1 — Ingest a document

```gherkin
Given a document containing PII such as an IBAN or email
When it is ingested
Then it is chunked and embedded
And no raw PII is stored in the vector store
```

### V2 — Query with citations and redaction

```gherkin
Given an indexed corpus
When a question is asked
Then the response contains an answer and citations to the top-k chunks
And the model received no raw PII
And an audit record was written
```

## API contract

- `POST /vaultrag/documents` — body `{doc_id, title, content}` → `{doc_id, chunks}`
- `POST /vaultrag/query` — body `{question}` → `{answer, citations[]}`

## Out of scope

- Tenant isolation and row-level security (W2)
- Hybrid BM25 + dense retrieval (later iteration)
- PDF ingestion (text/Markdown only for now)
- Postgres/pgvector persistence (in-memory store for now)
